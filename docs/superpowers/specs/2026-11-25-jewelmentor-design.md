## 2. 方案比较

| 方案 | 优点 | 代价 | 判断 |
| --- | --- | --- | --- |
| 单页面聊天 + 单个 Prompt | 容易演示、开发快 | 难以检验交接、恢复、评测和工程可靠性 | 不足以覆盖简历描述 |
| FastAPI 模块化单体 + SQLite + 原生网页 | 核心控制流可审计，本地复现成本低，可替换模型与存储 | 需要自行定义清晰的 Harness 和协议 | 推荐；等待用户确认 |
| 多服务 + 消息队列 + 图数据库 + 独立前端 | 适合组织级部署与横向扩容 | 基础设施占用演示精力，增加首次运行难度 | 留作演进路径 |

不以框架名称数量作为能力证明。关键状态、边界、错误和证据由项目代码显式体现。

## 3. 用户流程与页面

默认页面为中文培训工作台，使用真实业务场景和可解释的执行轨迹。

```text
┌ JewelMentor · 珠宝销售训练                        Demo / Live ┐
│ 场景：价格异议   专家：顾问式教练   会话：…                  │
├─────────────────────────────┬─────────────────────────┤
│ 对话与练习                   │ 本轮执行                │
│ 用户：顾客觉得钻戒太贵了…     │ 意图 → 专家 → 知识      │
│ 教练：… 引用 [kb-…]          │ 状态与重试次数          │
│ 下一步练习 / 发送             │ 轨迹事件与质量反馈      │
└─────────────────────────────┴─────────────────────────┘
```

用户可以创建会话、选择专家、提交问题、在同一会话切换专家并查看前文；也可以进入演示场景，查看知识来源和本轮轨迹。界面明确区分离线模板输出与实时模型输出，不展示密钥。

## 4. 三层 Agent 与交接协议

### Supervisor Agent

接收请求、检查会话和输入、执行意图路由、维护执行预算、创建规范交接信封、调度下层节点并汇总响应。低置信度或存在冲突的意图返回澄清，避免强行套用专家。显式请求切换专家优先于历史默认偏好。

### Recommendation Agent

从 Skill 注册表根据场景标签、用户选择与训练目标选择销售专家。至少提供三个原创虚构角色：顾问式需求挖掘、价值呈现与异议处理、长期客户关系。返回角色 ID、选择理由及适用边界。

### Dialogue Agent

组合角色、知识证据、会话最近消息和经过筛选的长期记忆。离线模式使用可预测的示例策略，在线模式生成有上下文的自然语言答复。知识不足时说明不足；优先给出示范话术、原理和下一步练习。

### HandoffEnvelope

采用强类型数据结构，包括 schema_version、trace_id、session_id、turn_id、source、target、intent、expert_id、goal、recent_messages、memory、evidence、deadline 和 remaining_hops。禁止向模型传入客户端任意指定的系统角色。验证目标、上下文预算和剩余跳数；拒绝非法交接并产生事件。

一次响应需包含最终答复、专家信息、意图与置信度、知识引用、provider、回合标识及可供查看的轨迹标识。

## 5. Harness：状态、失败与恢复

状态机：

```text
PENDING → ROUTING → RECOMMENDING → RETRIEVING → GENERATING → COMPLETED
                                       └ 失败 → RETRYING → 原节点
可恢复异常耗尽预算 → DEGRADED
协议违规 / 不可恢复异常 → FAILED
```

- 显式状态转移表，非法转移不能静默通过。
- 事件字段包含事件 ID、trace/session/turn、节点、状态、时间、尝试次数、耗时和有限错误类别。
- 每个节点有超时和有限重试，整体执行有时间预算与跳数预算。只重试临时网络、限流或可恢复错误；参数和协议错误不重试。
- 使用 SQLite 事务保存会话、消息、回合、事件和 checkpoint。进入节点、完成节点及终态均保留审计信息。
- 同一会话串行更新，不同会话可并发；同一请求的幂等键避免重复写入。SQLite 单机部署边界在文档中明确。
- 正常会话历史在进程重启后可加载。中断回合的恢复根据最近的持久化 checkpoint 继续执行，具有明确入口和测试，不将「保存了 JSON」等同于完整恢复。
- 多专家会话保留公共会话上下文，但角色私有设定不跨角色混用。
- 异常降级必须返回降级状态及原因类别，保留已经提交的上下文；不把降级当作成功交接统计。
- 通过受控测试模拟慢模型、超时、临时故障、异常交接、超预算、重复请求与重启。

## 6. Persona Skill 与知识

Skill 是可校验的 JSON 或 YAML 数据，包括身份、成长阶段、价值观、风格、场景标签、示范对话、禁区与版本号。角色全部使用原创虚构背景，避免把未经核实的信息当作真实人物生平。

短期记忆保存最近若干轮，长期记忆仅保存与训练相关的结构化内容，例如训练目标、掌握程度、偏好；不把用户任意文本提升为高优先级指令。限制消息和记忆长度并提供清理入口。模型上下文中显式区分系统约束、角色资料、历史消息和不可信检索内容。

内置小规模珠宝销售教学知识集，包括需求挖掘、预算、4C 基础、价格异议、售后边界和合规销售。每条记录有稳定 ID、标题、正文、标签与来源说明。检索采用可解释的轻量中文词项与标签评分，返回可点击或可查询的引用。公开说明其为教学语料和词法检索，向量召回/Rerank 作为替换接口与未来方向，不声称已实现。

## 7. Provider 与 API

Provider 协议隔离模型依赖，支持：

- DemoProvider：无网络、无密钥，适合 CI 与首次体验；输出标注为离线演示。
- OpenAICompatibleProvider：从环境读取 API Key、base URL 与 model；使用异步 HTTP、超时、响应结构验证和适当错误分类。

计划接口：

- `GET /health`：健康和模式信息，不泄露配置秘密。
- `GET /api/experts`：专家目录。
- `POST /api/sessions`：创建会话。
- `GET /api/sessions/{id}`：读取会话。
- `POST /api/sessions/{id}/messages`：提交消息，可带专家选择与幂等键。
- `GET /api/sessions/{id}/traces`：会话轨迹。
- `GET /api/knowledge/{id}`：知识证据。
- `DELETE /api/sessions/{id}`：清理会话与关联记忆。

默认绑定 localhost，公开说明本地演示版本没有生产级身份认证。错误返回一致结构，限制输入长度；避免在浏览器里拼接未经转义的对话 HTML。无需在第一版引入流式协议；以可恢复和可核验的完整回合为先。

## 8. 评测闭环与指标口径

版本化评测集包含正常路由、模糊输入、显式切换、知识问题、提示注入和跨轮上下文。与运行日志隔离并写明这是合成/人工编写的公开演示样本。

- 意图准确率：正确分类数量 / 有标签样本数量，同时给出各类数量、混淆与失败样本。
- 交接成功率：按协议到达预期终态的任务 / 尝试任务；测试集包含故障注入并单列降级与失败。
- 角色一致性：可复现的规则代理分，检查风格约束、身份泄漏、结构要素等；不将其称为真实用户还原度。
- 学习效果：训练反馈是否给出可操作示范、解释与练习的代理覆盖率；真实效果需要训练前后测与人类评价。
- 失败归因：至少分为 routing、prompt_boundary、retrieval、provider、handoff、runtime，并输出待修复案例。

公开报告记录命令、数据版本、provider、样本量、时间、环境、结果和限制。真实模型评测仅在有用户提供配置时运行，外部调用成本与版本敏感性写入说明。

简历中的 94%、96%、98.2% 仅作为原经历中给出的指标，不能被未经验证地写成此仓库结果。README 指标表将明确标记「简历描述 / 本仓库实测 / 测量方法」，或直接仅展示本仓库可复现的结果。
